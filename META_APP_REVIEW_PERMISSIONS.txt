META APP REVIEW - PERMISSION USE CASES
Iris OS Meta Integration

Overview

Iris OS is an agency workspace that allows an authorized agency administrator to connect Meta advertising assets, assign a connected ad account to a client, view read-only advertising performance, and receive Facebook Instant Form leads for that client. The integration is initiated only by an authenticated organization administrator in Settings > Integrations. Iris OS stores the authorization token encrypted at rest and uses it only for the flows described below. The application does not create, edit, pause, publish, or delete Meta campaigns, ads, creatives, Pages, or Business Portfolio assets.

public_profile

Iris OS uses public_profile to identify the Facebook user who explicitly authorizes the Meta connection. After authorization, the application reads the user's Meta ID and display name from the /me Graph API endpoint. This information is saved with the encrypted connection so the organization can see which authorized user established the connection and so the server can validate that the returned access token belongs to the expected Meta user. The profile information is not exposed to clients and is not used for advertising, profiling, or any purpose outside connection administration.

email

Iris OS requests email to display the email address of the user who authorized the Meta connection, when Meta makes an email address available. The address provides an audit-friendly connection context to the agency administrator in Settings and helps the agency distinguish between multiple authorized Meta users. Meta may not return an email address for every account; the integration continues to operate without it. Iris OS does not use this permission to contact Facebook users, build marketing audiences, or share the address with client users.

ads_read

Iris OS uses ads_read solely to retrieve read-only advertising assets and delivery data for ad accounts to which the authorizing Meta user has access. During connection setup, the application calls /me/adaccounts to list accessible ad accounts and their basic context, such as account name, account ID, status, currency, Business Portfolio association, and access tasks. The agency administrator selects the accounts the organization intends to connect. When an administrator opens a client record and selects Sync Account Metrics, Iris OS retrieves that selected account's campaigns, ads, and ad-level insights, including spend, reach, impressions, and clicks. These values are shown in the client detail page as Meta-synced performance data. Iris OS does not use ads_read to change advertising settings or perform any write operation.

business_management

Iris OS uses business_management to discover the Business Portfolios available to the authorizing Meta user and to understand the business ownership context of accessible ad accounts. During setup and refresh, the application requests /me/businesses and reads the Business Portfolio ID and name associated with returned ad accounts. The information is presented to the agency administrator in the Meta account-selection interface, alongside the ad account name, account ID, currency, and status. This allows the administrator to select the correct account when an agency manages assets across more than one Business Portfolio. Iris OS does not create, modify, assign users to, or otherwise administer Business Portfolios; the permission is used only for asset discovery and connection context.

leads_retrieval

Iris OS uses leads_retrieval to retrieve the details of a Facebook Instant Form lead after Meta sends the application a leadgen webhook notification. The webhook notification contains a lead ID rather than the complete lead response. Iris OS uses the Page access token to retrieve that lead's ID, created time, source ad ID, form ID, campaign ID, and submitted field data. The application normalizes supported contact fields such as full name and email, then stores the lead in the agency workspace. Before saving, it resolves the source ad's ad account and checks that the account was selected for the organization and explicitly assigned to a client. Leads from unconnected accounts or accounts without a client association are ignored. Authorized agency users can view the relevant leads, and authorized client users can view only leads belonging to their own assigned account. Iris OS uses the lead information for agency/client lead follow-up and reporting; it does not sell, share, or use lead data to build unrelated audiences.

pages_show_list

Iris OS uses pages_show_list to discover the Facebook Pages that the authorizing Meta user can manage. During connection setup and refresh, the application calls /me/accounts and receives the Page ID, Page name, Page tasks, and Page access token needed for the lead retrieval workflow. The application stores a mapping between each discovered Page and the organization's encrypted Meta connection. The Settings interface tells the administrator how many manageable Pages were found and warns when no Pages are available, because Instant Form lead retrieval cannot operate without a manageable Page. Iris OS does not publish Page content, read Page posts, or manage Page community activity through this permission.

pages_manage_metadata

Iris OS uses pages_manage_metadata exclusively to subscribe manageable Facebook Pages to the application's Instant Form lead webhook. After the agency administrator selects one or more accessible Meta ad accounts, Iris OS sends a POST request to each discovered Page's /{page-id}/subscribed_apps endpoint with subscribed_fields set to leadgen. This subscription enables Meta to notify Iris OS when a new Instant Form lead is generated on that Page. The application then uses the notification only to retrieve and route the corresponding lead as described in the leads_retrieval use case. Iris OS does not modify Page profile information, Page settings, Page content, or other Page metadata. The permission is necessary only to establish and maintain the leadgen webhook subscription.

Permission validation and user control

At connection time, Iris OS validates the Meta token and checks that all required permissions were granted. If a required permission is absent, the integration is not activated and the administrator receives an error identifying the missing permission. Administrators choose which discovered ad accounts to connect, can associate an account with a specific client, and can disconnect the Meta integration from Settings. The application only displays client lead and advertising data for clients with an explicitly associated Meta ad account.

Permissions not requested or used

Iris OS does not request pages_manage_ads or ads_management. The application has no interface or server action for creating, editing, pausing, publishing, deleting, budgeting, or otherwise managing Meta ads or Page ads. Campaign and ad mutation endpoints are intentionally blocked. Advertising data is read from Meta using ads_read and displayed as read-only, Meta-synced data. If Iris OS adds provider-side advertising management in the future, it will request the appropriate permissions and submit the relevant use case for review before enabling that functionality.
